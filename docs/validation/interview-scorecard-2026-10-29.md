# Scorecard de entrevistas y pruebas — 2026-10-29

## Propósito

Convertir el guion de entrevistas en evidencia comparable sin publicar contactos, nombres personales, correos, teléfonos, facturas reales ni conversaciones identificables. Este archivo es una plantilla: no contiene clientes ni resultados.

## Registro mínimo por organización

Usar un identificador anónimo (por ejemplo, `ORG-001`) y completar sólo después de una conversación efectivamente realizada y autorizada.

| Campo | Valores permitidos |
|---|---|
| ID anónimo | ORG-### |
| Segmento | PyME B2B / agencia / estudio / consultora |
| Fecha de entrevista | AAAA-MM-DD |
| Canal autorizado | llamada / videollamada / otro autorizado |
| Proceso actual | planilla / ERP / correo / mixto / otro |
| Dolor principal citado | texto agregado, sin datos personales |
| Frecuencia del problema | única / recurrente / no confirmado |
| Prioridad útil | sí / parcial / no / no probado |
| Motivo entendido | sí / parcial / no / no probado |
| Borrador corregido o aprobado | sí / parcial / no / no probado |
| Resultado observable | tiempo / errores / seguimiento / auditoría / ninguno |
| Acepta repetir prueba | sí / no / pendiente |
| Evidencia autorizada | referencia privada / resumen autorizado / ninguna |
| Próxima acción | revisar / prueba / seguimiento / cerrar |

## Reglas de conteo

- Una entrevista cuenta sólo si hubo conversación real y registro privado autorizado.
- Un dolor recurrente cuenta cuando el mismo problema agregado aparece en **tres organizaciones independientes**.
- Una prueba cuenta sólo si se ejecutó el flujo del cockpit con datos ficticios o datos entregados voluntariamente.
- Un piloto pago cuenta sólo con un pago comprobable; US$29 por 30 días sigue siendo una hipótesis hasta entonces.
- Una visita al sitio, una apertura de demo o una respuesta automática no cuentan como entrevista, prueba ni cliente.

## Criterio de avance del MVP

Considerar una prueba útil cuando la organización:

1. identifica una prioridad sin explicación adicional;
2. entiende el motivo de la recomendación;
3. corrige o aprueba el borrador;
4. declara un resultado observable;
5. acepta repetir el flujo con alcance y datos autorizados.

Registrar cada criterio como sí / parcial / no, sin convertirlo en porcentaje de conversión hasta tener un denominador real.
