# Checklist de prueba y piloto — 2026-10-29

## Estado

Preparación operativa para validación manual. No es una oferta activa, no registra clientes y no procesa pagos.

La ejecución requiere autorización explícita del propietario y de la organización participante. La aplicación no contacta, cobra ni almacena datos de clientes.

## Antes de una prueba

- [ ] Existe una organización identificada sólo por un ID privado, por ejemplo `ORG-001`.
- [ ] La persona autorizó la conversación y el uso de datos ficticios o de un CSV entregado voluntariamente.
- [ ] Se acordó el alcance: CSV/Excel, priorización, explicación del motivo, borrador y aprobación humana.
- [ ] Se confirmó que no se usarán credenciales, facturas reales no autorizadas, datos bancarios ni información sensible.
- [ ] Se definió cómo retirar los datos al finalizar, si se usaran datos autorizados.

## Ejecución de la prueba

1. Registrar el ID anónimo, segmento y fecha en una hoja privada.
2. Usar primero el CSV ficticio o una copia autorizada con las columnas documentadas.
3. Mostrar la proyección a 7/30 días y las tres prioridades.
4. Pedir a la persona que explique cuál atendería primero y por qué.
5. Abrir el detalle de prioridad y revisar el borrador.
6. Registrar si corrige, aprueba o rechaza el borrador.
7. Registrar un único resultado observable: tiempo, errores evitados, seguimiento ordenado, auditoría o ninguno.
8. Exportar el plan local sólo si la persona lo solicita; explicar que no se envía ni persiste.
9. Eliminar la copia local o confirmar su devolución según lo acordado.

## Criterio para contar una prueba

Una prueba cuenta sólo si el flujo se ejecutó con una persona real y autorización documentada. Deben estar registrados:

- prioridad entendida;
- motivo entendido;
- borrador corregido o aprobado;
- resultado observable;
- decisión sobre repetir la prueba.

Una demostración interna, una visita a la página o un archivo ficticio sin participante no cuentan.

## Antes de ofrecer el piloto

- [ ] Hay al menos dos pruebas registradas con resultados observables.
- [ ] Los dolores recurrentes se basan en tres organizaciones independientes, no en opiniones inventadas.
- [ ] La organización pide explícitamente continuar.
- [ ] El alcance, duración, datos permitidos y soporte están escritos.
- [ ] La hipótesis de precio se presenta como hipótesis: US$29 por 30 días, hasta 50 facturas.
- [ ] La aceptación y cualquier pago se comprueban fuera de este repositorio, sin publicar comprobantes ni datos personales.
- [ ] No se promete envío automático, integración, ahorro o resultado que todavía no esté probado.
